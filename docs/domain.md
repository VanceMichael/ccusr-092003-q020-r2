# 领域资料

## 问题背景

东北多地同时申报面向东北亚的算力项目。低电价档位、变电容量、工业数据授权、跨境服务意向取自**不同日期**，若直接拼接，会把尚未落实的资源误判为建设条件。本系统以“**评审轮次锁定证据版本**”为核心解决该问题。

## 六个评估维度

| 维度 | 含义 | 证据主体 |
| --- | --- | --- |
| `power_window` | 园区低电价档位及执行窗口 | 园区 `site_ref` |
| `datacenter_stage` | 机房建设阶段与可用容量 | 园区 `site_ref` |
| `data_scope` | 工业数据授权覆盖类别 | 数据集合 `data_collection_ref` |
| `residency` | 数据驻留与出境限制 | 政策证据（无单一主体） |
| `research_grant` | 科研合作是否正式授权 | 科研项目 `research_grant_ref` |
| `service_region` | 可服务区域（境内/跨境） | 政策证据（无单一主体） |

## 证据版本与锁定

- 每份证据分版本登记：`draft → issued → superseded/withdrawn`，每版带生效窗口
  `effective_from/effective_to` 与材料受控引用 `payload_ref`、`payload_sha256`。
- 每个评审轮次中，每方案每维度只能锁定一个版本；锁定时复制**快照**（状态、窗口、结构化
  事实、引用、摘要），轮次内不可更换。新版本的出现不改变已锁内容。
- 只有锁定时点处于 `issued` 且生效窗口内的版本可锁定——草案、未生效、已失效的材料一律
  拒绝，从机制上杜绝“把不同日期材料拼出建设条件”。
- 证据主体必须与方案引用的园区/数据集合/科研项目一致，防止张冠李戴。

## 容量并发预留

- 变电节点的承诺容量 `committed_mw` 本身分版本，带生效日期。
- `POST .../capacity` 在单个 `BEGIN IMMEDIATE` 事务中读改写，并由数据库触发器兜底：
  节点全部 `held` 预留之和不得超过锁定所依据承诺版本的承诺值，并发请求下也不会超售。
- 容量被其他项目占用后，**只影响尚未锁定的方案**；已 `held` 的预留不随后续承诺值下调
  或他项占用而改变。方案被驳回时释放其预留。

## 跨境与不出域口径

- 同一方案同时按 `cross_border` 与 `domestic` 两种口径评估。
- 跨境缺口仅为 `cross_border_not_permitted`（驻留不允许出境）或
  `service_region_domestic_only`（仅取得境内服务意向）时，可自动降级按**数据不出域**口径
  参与比较与批准；若还叠加数据类别、机房阶段、科研授权等硬性缺口，则两种口径都不可比。

## 隐私边界

- 外部主体一律使用不含真实身份信息的引用编号；交换时间使用带偏移量的 ISO 8601 字符串。
- 原始材料只保存受控引用与 `sha256` 摘要；接口入口递归拒绝 `raw_data` 等原始字段，
  `fact` 仅接受各维度白名单字段（见 `contracts/entities.json`）。决策人员看不到企业
  原始数据。

## 决策与历史

- 批准要求：所选口径六维无缺口，且容量已 `held`。决策行不可变，冻结内容包括六维版本
  快照、当时承诺值版本与占用总量、两种口径的完整缺口判定。
- 证据版本事后被取代/撤回、承诺值事后调整、其他项目事后获批占用容量，都只作为
  **后续变化（history）**追加呈现，与冻结的“当时为何可行”严格分开，绝不回写。
- 历史页分三部分：`frozen_snapshot`（原判断依据）、`subsequent_changes`（系统对照出的
  现行差异）、`subsequent_notes`（事件时间线与人工附注）。

`contracts/entities.json` 中的字段名称、维度、缺口码属于稳定接口约定；运行时数据文件
位置由 `DATABASE_PATH` 决定。
